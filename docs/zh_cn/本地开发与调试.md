# 本地开发与调试

根目录 `README.md` 里的「即刻开始」仍按模板仓库来写。下面按本仓库实际的脚本和界面配置说明怎么在本地跑起来。作者当前用 MuMu 模拟器调试，这一节末尾的地址和分辨率是这套环境的记录，源码里没有写死它们。

## 依赖

- Git，用来克隆仓库和子模块
- Python 3，用来跑 `tools/` 和 `check_resource.py`。CI 用的是 GitHub `ubuntu-latest` 上的系统 Python，仓库没有锁定小版本
- Node.js。检查工作流里 `maa-checker` 使用 Node 22
- 一份 MaaFramework 发行包，解压后要能看到 `deps/bin`
- Adb。控制器类型是 `Adb`

Windows 上若 MaaPiCli 或 MaaDebugger 提示缺少运行库，模板 README 的 FAQ 给出的安装包是 [vc_redist](https://aka.ms/vs/17/release/vc_redist.x64.exe)。

## 拿到代码和 OCR 模型

```bash
git clone --recurse-submodules https://github.com/82488059/MAAJN.git
cd MAAJN
```

已经克隆过、子模块是空目录时：

```bash
git submodule update --init --recursive
```

`.gitmodules` 把 `assets/MaaCommonAssets` 指向 `https://github.com/MaaXYZ/MaaCommonAssets`。`tools/configure.py` 从这个子模块复制中文 OCR：

- 来源：`assets/MaaCommonAssets/OCR/ppocr_v5/zh_cn`
- 目标：`assets/resource/model/ocr/`

目标目录还不存在时才会复制。目录已经存在就打印 `Found existing OCR directory, skipping default OCR model import.` 并跳过。子模块路径 `assets/MaaCommonAssets/OCR` 不存在时，脚本直接退出，即使 `model/ocr` 里已经有文件也一样。发布工作流使用 `actions/checkout` 的 `submodules: true`，走的就是这条复制路径。

模板 README 还写了另一种放模型的办法：下载 [ppocr_v5-zh_cn.zip](https://download.maafw.xyz/MaaCommonAssets/OCR/ppocr_v5/ppocr_v5-zh_cn.zip)，解压到 `assets/resource/model/ocr/`，得到：

```text
assets/resource/model/ocr/
├── det.onnx
├── keys.txt
└── rec.onnx
```

`assets/resource/model/.gitignore` 忽略了 `ocr`，模型不要提交。OCR 加载失败、日志里出现 `Failed to load det or rec` 或 `ocrer_ is null` 时，先确认上面三个文件在这个目录。

本地只想把模型放进资源目录时：

```bash
python tools/configure.py
```

`install.py` 使用 `from configure import configure_ocr_model`，需要在 `tools/` 目录里执行。`configure.py` 按文件位置找资源，在仓库根目录执行也可以。

## 放入 MaaFramework

从 [MaaFramework Releases](https://github.com/MaaXYZ/MaaFramework/releases) 下载与本机系统、架构匹配的压缩包，解压到 `deps/`，保证存在 `deps/bin`。`tools/install.py` 找不到这个目录会退出，并提示先下载 MaaFramework。

`.gitignore` 忽略 `deps/*`，只保留 `deps/tools/*.schema.json`。框架二进制不要提交。

## 连接模拟器并运行

`interface.json` 只声明了一个控制器：名称「安卓端」，类型 `Adb`，`display_short_side` 为 `720`。它不包含主机、端口或分辨率。

作者本地调试环境：

- 模拟器：MuMu
- ADB 地址：`127.0.0.1:16448`
- 分辨率：900×1600，竖屏

先让本机 adb 看到设备：

```bash
adb connect 127.0.0.1:16448
adb devices
```

然后用下面任一方式跑任务。

### MaaPiCli

MaaFramework 发行包的 `bin` 目录里有 MaaPiCli。解压到本仓库后就是 `deps/bin/MaaPiCli`（Windows 为 `deps\bin\MaaPiCli.exe`）。在交互界面里选择 Adb 控制器「安卓端」，设备使用上面的地址。

资源名是「官服」，路径 `./resource`，相对 `interface.json` 所在目录。直接对源码运行时，界面对应 `assets/interface.json`，资源对应 `assets/resource`。界面任务以 `interface.json` 的 `task` 为准（当前 13 项，含自动买药、一条龙、炼药、买钱袋、离开/返回百业、找温无双、退出游戏、存放原料等），完整列表见 [项目概览](项目概览.md)。炼药与买钱袋需要 Agent（`interface.json` 已启用 `python ./agent/main.py`）；跑这两项或一条龙前请确认本机 Python 能启动 Agent。

`tools/install.py` 在组装桌面安装包时会排除文件名匹配 `*MaaPiCli*` 的文件。打好的桌面包装进的是 MFAAvalonia，不是 MaaPiCli。Android 包不下载 MFAAvalonia，`deps/bin` 会原样复制到 `install/`。

### 编辑器里的流水线调试

`.vscode/extensions.json` 推荐 [Maa Pipeline Support](https://marketplace.visualstudio.com/items?itemName=nekosu.maa-support)。模板说明里写到它能调试节点、截图、取 ROI 和取色。`.vscode/settings.json` 已把 pipeline JSON 和 `interface.json` 分别绑到 `deps/tools/pipeline.schema.json`、`deps/tools/interface.schema.json`。

运行期日志和调试输出不在仓库里。`.gitignore` 忽略了 `debug` 和 `config`。模板 README 提到出问题时带上 `debug/maa.log`。Issue 模板提到把 `config/maa_option.json` 里的 `save_draw` 设为 `true` 后，识别可视化在 `debug/vision`。

### 本地组装安装目录

和 CI 相同的组装命令（示例版本号和平台按本机修改）：

```bash
cd tools
python -m pip install -r requirements.txt
python install.py v1.0.0 win x86_64
```

`install.py` 的参数是 `<version> <os> <arch>`。`os` 可以是 `win`、`macos`、`linux`、`android`，`arch` 可以是 `x86_64`、`aarch64`。少参数会打印用法并退出。

它会：

1. 把 `deps/bin` 按平台拷进 `install/`。桌面平台放到 `runtimes/<dotnet-rid>/native`，并跳过 `MaaDbgControlUnit`、`MaaThriftControlUnit`、`MaaRpc`、`MaaHttp`、`plugins`、`*.node`、`MaaPiCli`。Android 则整份 `bin` 拷到 `install/`
2. 桌面平台另把 `deps/share/MaaAgentBinary` 拷到 `install/libs/MaaAgentBinary`，把 `deps/bin/plugins` 拷到 `install/plugins/<dotnet-rid>/`。Android 把 `MaaAgentBinary` 拷到 `install/MaaAgentBinary/`
3. 调用 `configure_ocr_model()`，再把 `assets/resource` 拷到 `install/resource`
4. 拷贝 `assets/interface.json`，把其中的 `version` 改成命令行传入的版本
5. 拷贝 `README.md`、`LICENSE` 和整个 `agent/`

`<dotnet-rid>` 由脚本按参数选择：`win-x64`、`win-arm64`、`osx-x64`、`osx-arm64`、`linux-x64`、`linux-arm64`。不在这六组里的桌面组合会退出。

`requirements.txt` 只有 `json-with-comments`，因为 `interface.json` 带注释。

这条命令只组装目录，不会下载 MaaFramework 或 MFAAvalonia。下载和打 zip 在 [发布流程](发布流程.md) 的 `install` 工作流里。

## Schema 校验和资源加载检查

检查工作流 `.github/workflows/check.yml` 在 `assets/**` 或任意 `**.py` 变更时运行。本地可以按同样的命令先跑一遍。

用 MaaFramework 自带工具检查 `interface.json`（需要 Node，工作流使用 Node 22）：

```bash
npx @nekosu/maa-checker@latest ./assets/interface.json --github=.
```

用 maafw 加载资源包。工作流安装的是预发布版：

```bash
python -m pip install --upgrade pip
python -m pip install --upgrade maafw --pre
python ./check_resource.py ./assets/resource/
```

`check_resource.py` 对每个传入目录调用 `Resource.post_bundle`。参数少于一个目录时打印用法并以状态码 1 退出。加载失败同样以状态码 1 退出。标准输出级别设为 `LoggingLevelEnum.All`。

用 JSON Schema 校验 pipeline 和 interface。工作流把 schema 版本锁在 `jsonschema==4.26.0`、`referencing==0.37.0`：

```bash
python -m pip install jsonschema==4.26.0 referencing==0.37.0
python tools/validate_schema.py \
  --schema-dir deps/tools \
  --resource-dirs assets/resource \
  --exclude-dirs assets/resource/announcement \
  --interface-files assets/interface.json
```

脚本默认的 `--schema-dir` 是 `tools/schema`，本仓库的 schema 实际在 `deps/tools`，所以要带上 `--schema-dir`。它会：

- 用 `pipeline.schema.json` 校验资源目录下全部 `.json` / `.jsonc`
- 用 `interface.schema.json` 校验指定的 interface 文件
- 只有传入 `--task-dirs` 时才用 `interface_import.schema.json`。工作流没有传这个参数
- 支持去掉 `//` 和 `/* */` 注释后再解析

`assets/resource/announcement` 在本仓库中不存在，排除项没有文件可跳过。`deps/tools/custom.action.schema.json` 和 `custom.recognition.schema.json` 不会被这个命令用到。

三个检查都通过时，资源脚本打印 `All directories checked.`，schema 脚本打印 `All validations passed!`。

只改 `docs/` 不会触发 `check` 和 `install` 工作流，需要时可以在 GitHub 上对这两个工作流做 `workflow_dispatch`。
